# The glass material

A recipe for Apple-style "liquid glass" UI in a WoW addon, built and measured for
GlassUnitFrames on WoW: Forever 1.60.1.70009, and shipped as the embedded library
**LibGlass-1.0** (moved here from GlassUnitFrames @ `09b6f0d`, where it was `Glass.lua`).

**Keep this file current.** Any change to `LibGlass.lua`, `Tools/make_textures.py` or the material
parameters updates this document in the same commit.

In the code samples, `Glass` is an instance: `local Glass = LibStub("LibGlass-1.0"):New()` (§5).

---

## 1. What can and cannot be done

Real liquid glass is a **backdrop effect**: it blurs and refracts whatever is drawn behind the
element, live. An addon has no shader access and no API that hands it the rendered scene, so
**true blur and refraction are out of reach**. The one tell that remains is that the world shows
through the body **sharp** rather than frosted.

Everything else is faked convincingly with layered textures. Measured on 70009: the result reads
as glass over warm sandstone and over dark grass (GlassUnitFrames' `docs/FOREVER-PROBE.md`).

What makes it read as glass, in order of importance:

1. **A translucent, cool, light tint.** Dark or warm tints read as smoked plastic.
2. **A thin, mostly clear rim with light concentrated on the top edge.** A thick, evenly bright
   rim reads as a chrome bezel or a plastic case. This is the single biggest lever.
3. **Specular glints** where the top edge turns into the corners, plus a faint catch-light on
   the inner lip at the bottom (light passing through the slab).
4. **Glossy, rounded bars** inside: masked fill, ADD gloss on the top half, inner shadow at the
   bottom.
5. Small touches: a faint top-down white wash, a soft drop shadow, faint grain, an occasional
   sheen sweep.

## 2. Client features it relies on (all measured working on 70009)

| Feature | API | Notes |
|---|---|---|
| 9-slice scaling | `Texture:SetTextureSliceMargins(l, t, r, b)` + `SetTextureSliceMode(Enum.UITextureSliceMode.Stretched)` | Margins are in texture pixels. Works on MaskTextures too, **except on boxes small in both directions** (see §6). |
| Rounded masks | `frame:CreateMaskTexture()`, `mask:SetTexture(file, "CLAMPTOBLACKADDITIVE", "CLAMPTOBLACKADDITIVE")`, `tex:AddMaskTexture(mask)` | Works on a `StatusBar:GetStatusBarTexture()` fill: rounded at 0%, 3%, 50% and 100%. The moving fill edge stays square. |
| Gradients | `tex:SetGradient("VERTICAL", CreateColor(...), CreateColor(...))` | Takes **colour objects**, not numeric RGBA. VERTICAL: min = bottom, max = top. |
| Additive highlights | `tex:SetBlendMode("ADD")` | |
| Sweeping sheen | `AnimationGroup` with Translation + Alpha, on a texture masked by a mask that stays put | The mask clips the moving texture throughout. |
| Texture files | Uncompressed 32-bit TGA, bottom-left origin, power-of-two sizes | New files load after `/reload`. Only a brand-new addon folder needs a restart. |

Pixel snapping made no visible difference at UI scales 0.64–0.71; the defaults are fine.

## 3. The textures

Generated by `Tools/make_textures.py` (Pillow + numpy). **Never hand-edit a `.tga`**: change the
generator and rerun `python Tools/make_textures.py`.

Conventions that prevent halos and keep colour a runtime choice:

- **Overlay textures are one RGB colour everywhere** (white for highlights, black for shadows),
  with the shape carried **only in alpha**. Filtering can't bleed a wrong colour into the edge.
- **Masks are white-on-black in RGB and alpha**, so they work whichever channel is sampled.
- **Rounded shapes come from a signed-distance function** (`rounded_rect_sdf`), antialiased with
  a smoothstep. Lighting uses the SDF gradient as the edge normal.

| Texture | Size | Radius / slice margin | What it is |
|---|---|---|---|
| `body_mask` | 64 | r14 / 16 | Rounded body mask |
| `body_mask_small` | 32 | r7 / 8 | Body mask for frames under ~40px tall |
| `rim5`, `rim_dark5` | 64 | r14 / 16 | **Current rim** and its dark companion |
| `rim5_small`, `rim_dark5_small` | 32 | r7 / 8 | Same material at half scale |
| `shadow`, `shadow_small` | 128 / 64 | margin 48 / 24 | Soft drop shadow (logistic falloff) |
| `bar_mask` | 32 | r5 / 8 | Rounded bar mask |
| `bar_edge` | 32 | r5 / 8 | 1px lit edge around bars |
| `bar_fill` | 64x16 | none | Greyscale ramp; colour via `SetStatusBarColor` |
| `gloss` | 64 | none | Top-half ADD highlight for bars |
| `grain` | 128 | tiled | Faint frost noise |
| `sheen2` | 256x64 | none | Diagonal streak for the sweep |
| `track_fade` | 256x8 | none | Horizontal alpha ramp for a bar's missing part |
| `disc_mask` | 256 | circle / **unsliced** | Disc body mask (r2), hosts from ~96px up |
| `disc_rim`, `disc_rim_dark` | 256 | circle / unsliced | The rim material on a circle, and its dark companion |
| `disc_shadow` | 256 | unsliced, outset 0.125 | Soft drop shadow for a disc |
| `disc_mask_small`, `disc_rim_small`, `disc_rim_dark_small`, `disc_shadow_small` | 64 | circle / unsliced | The same at 64px, for discs under ~96px |

These 23 are all `Media\` holds (`tests/test_media.lua` checks it against the code). The earlier
iterations (`rim`…`rim4`, `sheen`) stay with GlassUnitFrames' `Tools/GlassProbe` for its A/B
comparison. **Texture names are part of the contract:** a frame keeps the path it was built with,
so a file is never renamed or repurposed within `LibGlass-1.0`; add a new one instead.

### The rim, `glass_rim(size, radius, k, light)`

One function draws the rim at any size. `k` scales every distance from the 64px design, and
`light` scales every highlight. The rim is the maximum of four alpha layers:

| Layer | Where | Brightness |
|---|---|---|
| Outer lip | a ~1px band on the outside edge | strongest along the top (`top^0.5`), some on the left, a little on the bottom |
| Inner lip | a ~1px band at the inside of the bevel | mostly the **bottom** (catch-light through the slab) |
| Slab | the bevel between the lips | very faint, brighter toward the top |
| Glints | Gaussian spots on the two top corner arcs | bright, clipped to the outer band |

The dark companion is a hairline just outside the rim, for contrast on bright scenery, plus a
faint line at the inner lip.

Current parameters: `rim5` = `glass_rim(64, 14, k=0.72, light=0.8)`, and
`rim5_small` = `glass_rim(32, 7, k=0.36, light=0.8)`.

The four layers live in `glass_lighting(d, glints, k, light)`, which takes any shape's SDF;
`glass_rim` gives it the rounded rect and the two corner glints (the rect textures are
byte-identical to r1's).

### The discs (r2), `circle_sdf`, `disc_rim`, `disc_shadow`

`circle_sdf(size, inset, radius?, dy?)` is the circle's signed distance (negative inside), so the
disc textures share the rect's coverage, `band`, normals and lighting:

- **`disc_mask(_small)`**: `mask(coverage(circle_sdf(size, 0.5)))`, white-on-black.
- **`disc_rim(_small)`, `disc_rim_dark(_small)`**: `disc_rim(size, k, light=0.8)` =
  `glass_lighting` on the circle. The normals of a circle point straight out, so the light from
  the top makes the outer lip brightest at 12 o'clock and the inner catch-light at 6. The glints
  sit where the rect rim's sit: on the arc 45° either side of the top (**10:30 and 1:30**), 0.15k
  inside the outer edge, clipped to the outer band. `k` = 0.8 at 256px (a ~5.6 texture-px bevel:
  7px on a 320px host) and 0.5 at 64px (~3.5 texture px: 2.2px at 40, 3.5px at 64).
- **`disc_shadow(_small)`**: `disc_shadow(size, outset=0.125, sigma, drop, alpha)`. The texture
  covers the host plus 0.125 of its size on every side (`SIZES.disc.shadowOutset`), so the disc in
  it has radius `size / 2 / 1.25` and lines up with the host at any size. Logistic falloff as
  the rect shadow (sigma 7 / 2.5, alpha 0.55 / 0.50), centred `drop` px lower (3 / 1) so the
  outset stays symmetric, and faded to 0 before the texture's edge so no hard circle shows.

Unsliced textures stretch with the host, so the bevel scales with it: use `disc` from ~96px
up and `disc_small` below (lines thinner than a pixel fade out when a 256px texture is drawn
small).

## 4. The layer stack (`LibGlass.lua`)

On a host frame, bottom to top:

| Layer | Draw layer | Region | Setting |
|---|---|---|---|
| Drop shadow | BACKGROUND -8 | host, outset by `shadowPad` | 9-sliced |
| Tint | BACKGROUND -6 | host, masked | `STYLE.tint` = (0.13, 0.16, 0.22, 0.24) |
| Grain | BACKGROUND -5 | host, masked, tiled | `STYLE.grain` = 0.45 alpha |
| Wash | BACKGROUND -4 | host, masked | white gradient, 0 at the bottom → `STYLE.wash` = 0.18 at the top |
| *content* | frame level host+2 (`Glass.ContentLevel(host)`) | caller's bars, models, etc. | inset by `Glass.Inset(size)` (6 / 3px) |
| Dark rim | OVERLAY 4 | `g.top` (level host+10) | 9-sliced |
| Sheen | OVERLAY 5 | `g.top`, own mask | optional |
| Rim | OVERLAY 6 | `g.top` | 9-sliced, at `STYLE.rimAlpha` (0.7, picked in game; `Glass.SetRimAlpha(a)` retunes every surface) |
| Text | OVERLAY 7 | `g.top` | `Glass.Font` |
| Edge (optional) | OVERLAY 7 / 5 / 7 | `g.top`, `g.edge` | a 1px top line, a short glow fading under it, and a 1px dark bottom line, kept `maskMargin - 2` px off the corners. **Off by default** (`STYLE.edge` = 0: hidden). `Glass.SetEdgeAlpha(a)` sets every surface's top line, with the glow and bottom line at `Glass.EDGE` ratios (0.27 / 0.78) over a 4px glow; `Glass.SetEdge(g, top, glow, bottom, glowh)` gives one host its own values, which the global tune then leaves alone |

A glass disc (`Glass.Disc(host, "disc"|"disc_small")`, r2) on a **square** host, bottom to top.
Its own builder, not `Apply` with a flag; it returns the same fields as `Apply` except `g.edge`,
which is `nil` (a circle has no top line):

| Layer | Draw layer | Region | Setting |
|---|---|---|---|
| Drop shadow | BACKGROUND -8 | host, outset on every side by `shadowOutset` (0.125) × the host's size | unsliced, symmetric |
| Tint, grain, wash | BACKGROUND -6 / -5 / -4 | host, `SetAllPoints`, masked by `g.mask` (`disc_mask`, unsliced) | as on a rect: `STYLE.tint`, `STYLE.grain`, `STYLE.wash` |
| *content* | host+2 (`Glass.ContentLevel(host)`) | caller's frames | `Glass.Inset("disc")` is the bevel at the texture's own size (6 / 3 px at 256 / 64); scale it by host size ÷ texture size |
| Dark rim | OVERLAY 4 | `g.top` (level host+10), `SetAllPoints` | unsliced |
| Sheen | OVERLAY 5 | `g.top`, own mask | optional: `Glass.Sheen(g, host, w, h)` works unchanged (its mask is the unsliced `disc_mask`) |
| Rim | OVERLAY 6 | `g.top`, `SetAllPoints` | unsliced, at `STYLE.rimAlpha`; registered with the instance, so `SetRimAlpha` and `TUNABLES` reach it |

- **The host must be square and sized before the call**: `Disc` errors when its width and height
  differ or are 0 (a frame sized only by anchors may not have resolved yet). The shadow's
  outset is computed from that size, so **resize a disc with `SetScale`**, not `SetSize`.
- `Apply` refuses a disc size, and `Disc` refuses `"large"`/`"small"`.
- `Glass.Mask(host, file, margin, ...)` with **`margin == nil`** (r2) is an unsliced mask stretched
  over the box. Content on a child frame needs its own:
  `Glass.Mask(child, "disc_mask", nil, inset, host)`, then `tex:AddMaskTexture(m)`.
- `SetEdge(g, ...)` on a disc does nothing, and `SetEdgeAlpha` never reaches one.

A glass bar (`Glass.Bar`), bottom to top:

| Part | Where | Notes |
|---|---|---|
| Background | bar, BACKGROUND | black 0.15, masked |
| Frost | bar, BACKGROUND 2 | white vertical gradient, 0 at the bottom → `STYLE.frost` 0.10 at the top |
| Fill | bar's StatusBar texture | `bar_fill`, masked, at `STYLE.fillAlpha` 0.60 (the texture's own alpha, re-applied after every colour change). Optional left-to-right fade to `STYLE.fillEnd` (1.0 = off, since the mockup's fill is even; `Glass.SetFillEnd`). Text sits on the host's `g.top`, so it stays opaque |
| Track | clip frame at bar + `Glass.TRACK_LEVEL` (1) | `track_fade` (256x8: alpha 1 over the first 30% of the bar, smoothstep to 0 at 85%) in the bar's own colour at `STYLE.trackTop` 0.75 via `SetVertexColor`. The ramp spans the whole bar, but its **clip frame starts at the fill's moving edge**, so it only shows past the fill: a full bar stays even, and it never doubles up under the translucent fill (`Glass.SetTrackAlpha`) |
| Caller overlays | bar + 2, + 3 | e.g. GlassUnitFrames' health-loss and heal-prediction bars |
| Gloss, inner shadow, edge | `bar.overlay`, bar + `Glass.OVERLAY_LEVEL` (4) | `gloss` (ADD, 0.45); inner shadow (bottom 45%, black 0.35 → 0; a `SetHeight` hook keeps it at 45% when the bar is resized); `bar_edge` |

`Glass.TUNABLES` lists the live-tunable knobs (key, `STYLE` field, setter, range, label, and
`default`: the instance's value when it was made, i.e. the shipped value plus the addon's
`opts.style`, before any saved setting), so any settings UI or slash command can expose them from
one definition. Each instance has its own list, its setters bound to it.

Every setter (`SetFillAlpha`, `SetRimAlpha`, `SetTrackAlpha`, `SetFillEnd`, `SetEdgeAlpha`,
`SetFont`) touches only the surfaces built through **its own instance**, and the bar hooks paint
with the bar's own instance's `STYLE`.

A `SetStatusBarColor` hook re-tints the fill and the track only when the colour actually changes
(painters recolour on every health and power event) and honours a 4th alpha argument. It
compares the new colour with the last one (`==`) and does arithmetic only on that plain alpha, as
v3 did. Pass it plain colours: whether `==` on a secret colour throws on this client is
unmeasured (Lua 5.1 can't make `==` throw in the test stub, so the tests can't catch it). The tuning
setters (`SetFillAlpha`, `SetRimAlpha`, `SetTrackAlpha`, `SetFillEnd`, `SetEdgeAlpha`) reject NaN.

All of them are masked by `bar_mask` (each child frame with its own mask anchored to the bar). The
gloss, inner shadow and edge live on **`bar.overlay`**, so anything drawn over the fill at bar
level + 2 or + 3 sits *under* the glass layers, like the fill itself. A hook keeps the overlay and
the track's clip at their offsets when the bar's level changes. What the three hooks need is
stored on the bar (`bar.glassState`), and each hook calls `lib.impl.OnBar*` when it runs, so a
newer copy of the library takes over bars an older one built (§5).

`Glass.Mask(host, file, margin, inset, anchor)` takes an optional `anchor`. A mask masks the
textures of its own frame, so a child frame gets its own mask anchored to the shape it must
follow.

**Liquid motion:** bars ease to new values with `StatusBar:SetValue(value, interpolation)`
(`Glass.Smooth()`, `Enum.StatusBarInterpolation.ExponentialEaseOut` when present). The client does
the easing, so it works with secret values.
- **Use `Glass.SetBar(bar, max, value, snap)`.** It passes the same interpolation to
  `SetMinMaxValues`, so a max change doesn't jump the fill and then slide back. If the client
  rejects the eased call, it falls back to an instant one.
- **Snap when the *unit* changes** (new target, pet swap, frame shown again), so the bar doesn't
  slide from the previous unit's value. GlassUnitFrames does this with a `frame.snap` flag set by
  full repaints. A periodic refresh of the *same* unit eases.
- **`Enum.StatusBarInterpolation` is not in the API dump:** without it, bars update instantly.

## 5. Using it in an addon

LibGlass-1.0 is **embedded**: each addon ships its own copy under `Libs\LibGlass-1.0\`, pulled in
by its `.pkgmeta`, and players never install it. LibStub runs the newest copy loaded, whichever
addon brought it.

1. `.pkgmeta`: the external, pinned to a tag (`tag: latest` picks the newest tag by creation
   date and falls back to branch HEAD), plus the library's non-dot ignores repeated under its
   folder, because **CurseForge's packager does not apply an external's own ignore list**:

   ```yaml
   externals:
     Libs/LibGlass-1.0:
       url: https://github.com/Spotnick2/LibGlass
       tag: r1
   ignore:
     - Libs/LibGlass-1.0/tests
     - Libs/LibGlass-1.0/docs
     - Libs/LibGlass-1.0/Tools
     - Libs/LibGlass-1.0/AGENTS.md
     - Libs/LibGlass-1.0/CLAUDE.md
     - Libs/LibGlass-1.0/README.md
   ```

   Bump the pin only in a release you are making anyway: players get library fixes earlier,
   from whichever addon ships the newer copy.
2. TOC, before the addon's own files: `Libs\LibGlass-1.0\LibGlass-1.0.xml`. Gitignore `Libs/`;
   for in-game testing of a dev checkout, `pwsh ..\LibGlass\Tools\deploy.ps1 -Addon <Addon>`
   copies it (only the shipped files, after checking none is missing) and prints its commit.
3. Make **one instance per addon** and keep calling it the way `Glass.lua` was called:

```lua
local Glass = LibStub("LibGlass-1.0"):New()      -- or New({ style = { rimAlpha = 1 }, font = "friz" })
local g   = Glass.Apply(frame, "large")          -- or "small" under ~40px tall
local bar = Glass.Bar(frame, 20)                 -- a glass StatusBar
bar:SetPoint("TOPLEFT", frame, "TOPLEFT", Glass.Inset("large"), -Glass.Inset("large"))
bar:SetFrameLevel(Glass.ContentLevel(frame))
local fs  = Glass.Font(g.top, 14, "LEFT")        -- text above the rim
local ag  = Glass.Sheen(g, frame, width, height) -- optional: ag:Stop(); ag:Play()
local d   = Glass.Disc(square, "disc")           -- r2: a round surface on a square, sized host
                                                 -- ("disc_small" under ~96px)
Glass.SetFont("friz")                            -- restyles this instance's Glass.Font strings
Glass.SetRimAlpha(0.5)                           -- this instance's surfaces only
```

- **Per instance:** `STYLE` (the defaults, then `opts.style`), `EDGE`, `fontKey` (`opts.font`),
  `TUNABLES`, and the surfaces the setters reach. An instance may change its own `STYLE` between
  `Apply` calls (AltStable's skin presets); it shows on what is built next.
- **Shared, read-only:** `MEDIA`, `SIZES`, `FONTS`, `TRACK_LEVEL`, `OVERLAY_LEVEL`. `MEDIA` is the
  winning copy's folder (`Interface\AddOns\<host>\Libs\LibGlass-1.0\Media\`) and changes when a
  newer copy loads. **Don't use it for your own art**: point your textures at your own folder.
  It is derived from the addon name the client passes, so **embed the library exactly at
  `<Addon>\Libs\LibGlass-1.0\`**. A copy nested anywhere else (inside another embedded library)
  would point every addon's new surfaces at a folder that doesn't exist, without an error, once it
  is the newest copy loaded. Nested embedding is unsupported in `-1.0` until it is measured
  (Phase 4 of `docs/PLAN.md`).
- **Region fields** you may retint, re-alpha or hide: `g.{size,shadow,mask,tint,grain,wash,top,
  dark,rim,edge}` (on a disc, `g.edge` is `nil`) and `bar.{glassMask,track,trackClip,overlay,trackColor}`. What the library
  repaints later is only what a setter owns (every rim's alpha after `SetRimAlpha`) and a bar's
  fill and track when its colour changes; an upgrade repaints nothing.

**Upgrades.** Within `LibGlass-1.0` the API only grows: nothing above is removed, renamed or
changes meaning (a breaking change is `LibGlass-2.0`, side by side). When a newer copy loads after
yours, your instance, its `TUNABLES[i].set` functions and the hooks on your bars run the newer
code from then on; it fills in only `STYLE`/`EDGE` keys your instance lacks and adds new
functions and `TUNABLES` entries, keeping your overrides and live-tuned values, and it never
repaints or rebuilds anything. **A builder change doesn't retrofit frames that were already
built.** If a newer copy fails while loading, `New` errors instead of handing out a half-loaded
library.

## 6. Gotchas

- **Slice margins vs. frame size.** A frame smaller than twice the slice margin still rendered
  in testing, but the corners get squeezed. Use the `small` set below ~40px tall.
- **Sliced masks fail on boxes small in BOTH directions.** Measured in a sibling glass addon on
  70009: a sliced `bar_mask`/`bar_edge` at margin 8 did not render correctly on 16-22 px
  **square** icon tiles. The same asset at margin 8 renders fine on bars that are small in one
  direction only (GlassUnitFrames' 300x12 and 330x7 power bars), and GlassUnitFrames' 32x32 pet
  portrait tile renders fine on `body_mask_small`. It isn't "short" that fails; which axis
  decides, and where the threshold sits between 22 and 32, is **unmeasured** (a settling test:
  three sliced tiles at 32x32, 64x20 and 20x64 in one screenshot).
- **Circles are never sliced, so discs work at any size.** A 9-sliced mask on a box small in
  both directions (under ~32px) is broken, as above, but the disc masks are unsliced: one texture
  stretched over the square host, so a 40px disc uses no slice margin at all. Pick `disc_small`
  under ~96px only so the rim's thin lines stay at least about a pixel wide.
- **Never scale a slice margin down to fit a small box.** Margins are in texture pixels and must
  match the generator (`bar_mask`/`bar_edge` are drawn at 32 px, radius 5, margin 8): a margin of
  4 cuts straight through the corner arc. A box too small for the asset's margin needs a smaller
  asset, not a smaller margin.
- **3D models can't be masked.** A `PlayerModel` draws a rectangle. Inset it inside the tile;
  its background is transparent, so the glass shows through behind the head, which looks good.
- **2D portraits come on black.** `SetPortraitTexture(tex, unit, true)` (`disableMasking`)
  gives a square portrait, but on an opaque black background that reads as a sticker in glass.
  Without `disableMasking` the client returns its own circular portrait on black corners.
- **Portraits must be refreshed on events** (`UNIT_PORTRAIT_UPDATE`, `UNIT_MODEL_CHANGED`,
  `PLAYER_ENTERING_WORLD`), not only set once at login, when they come back blank.
- **Text over glass** needs a shadow (`SetShadowOffset(1.5, -1.5)`, opaque black; 1 unit at black
  0.9 washed out over pale bars, since 1 UI unit is under a pixel at a 0.64 scale). Arial Narrow
  (`Fonts\ARIALN.TTF`, client-shipped) reads more modern than Friz Quadrata; it's the default.
- **The sheen at full brightness washes out text.** Keep its alpha ≤ 0.8 with the narrow
  `sheen2`, and trigger it on events (e.g. a new target), never continuously.
- **Frame levels:** everything that must sit above the rim goes on `g.top`. A child frame of the
  host otherwise draws over the host's own OVERLAY regions.
